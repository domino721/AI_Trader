# CR-0004 — PM의 포트폴리오 이론 책임과 최종 결정 백테스트

- 날짜: 2026-10-19 (한국 시간)
- 버전: 실행 계획 1.3.0 → 1.4.0 (minor)
- 결정 근거: 사용자가 포트폴리오 이론 담당 역할을 설계에 명시하고, 회의의 최종 의견으로 내린 의사결정도 백테스트할 수 있게 설계하라고 지시함.
- 이번 산출물: 역할·계약·평가·완료 기준의 설계와 계획 검증기 갱신. 실제 PM/LLM/역사적 백테스트 구현·실행은 후속 WBS 상태를 유지함.

## 기존 설계와 변경

기존 PM은 목표 비중·기간·현금·비용 조정을 맡지만 상관·공분산·위험 기여도 계산과 실패 처리가 구체적이지 않았습니다. 백테스트도 단계 목표는 있으나 최종 결정을 입력으로 재생하는 계약이 부족했습니다.

- 기존 PM을 **포트폴리오 매니저/포트폴리오 이론 담당**으로 명시합니다. 분산 투자, 상관·공분산, 종목/섹터/팩터/ETF 중복 노출, 위험 기여도, 제약·비용을 고려한 비중 구성을 담당합니다. 수치 계산·최적화는 코드, 선택 이유·반론은 LLM으로 분리합니다.
- 최종 회의 제안, 위험 검사 후 실행 결정, 실제 가상 체결을 별도로 기록합니다. 변경 없음·보류·거부·실패·미체결도 전체 결정 시계열에 남깁니다.
- 과거 시점별 전체 의사결정 생성과 저장된 결정의 오프라인 재생을 나눕니다. 후자는 LLM을 다시 호출하지 않으며 최초 결정의 시점 적합성까지 입증하지는 않습니다.
- 토론 유무 × PM 배분 유무의 비교, 연속 회계, 비용/지연, walk-forward·미사용 구간·LLM 지식 오염 한계를 완료 기준에 포함합니다.
- 상세 계약과 검증 사례는 [포트폴리오·최종 결정 백테스트 설계](../PORTFOLIO_BACKTEST.md)에 둡니다.

## 대안과 선택

별도 찬성표를 추가하는 포트폴리오 분석가 대신 기존 PM의 책임을 확장합니다. 종목 선택과 자산 배분의 기여를 분리하고, 같은 신호를 표 수로 중복 계산하지 않기 위해서입니다. 단순 평균은 비교군으로 유지하며, 평균–분산·최소분산·리스크 패리티는 사전 고정한 실험 정책으로 비교합니다. 특정 최적화 방식·기대수익률·실운용 한도는 이번에 확정하지 않습니다.

의존 경로에서 추가 작업량은 **7일**입니다. 3.3은 D+40–45, 4.2는 D+55–63, 연구 종료는 D+67 → 74, 전체 계획 종료는 D+118 → 125로 이동합니다. 기존 D+0 기준점은 유지하고 새 기준선 수립일만 2026-10-19로 기록합니다. 이는 달력 납기 약속이 아니며, 모델·데이터 접근성과 전향 관찰 기간에 따라 재예측합니다. 추가 역할 설명·계산·실험 조합은 LLM 호출/저장/계산 비용을 늘릴 수 있어 WBS 3.1에서 실험별 예산과 중단 조건을 고정합니다. 유료 계약·새 의존성은 추가하지 않습니다.

WBS ID·의존 순서·기존 완료/진행/차단 상태와 데이터 확장 1.9–1.19·대상 Windows 수용 0.6·실제 모델 3.1 게이트는 유지합니다. 데이터 외부 게이트를 설계 변경으로 통과 처리하지 않습니다. 최신 런타임의 네트워크/변수 설정 준비 상태와 실제 공급자 기능 검증도 구분합니다.

## 기준선과 검증

원격 v1.3.0을 기반으로 v1.0–v1.3 원문·해시는 보존합니다. 기존 CR-0002(운영 기반)·CR-0003(데이터 확장)은 유지하며 이번 변경은 CR-0004로 분리합니다. 기존 2.1은 완료 기록을 유지하고 새 포트폴리오 문헌 수용은 3.3에서 수행합니다. `docs/baselines/v1.4`에 이번 설계·결정·CR·WBS와 해시를 고정하고 `plan-v1.4.0` 태그로 남깁니다. 검증기는 기존 기준선과 새 기준선의 무결성, 등록된 계획 버전/CR, WBS 범위·일정·선행 게이트·완료 근거를 함께 검사합니다. `bash scripts/check.sh` 결과와 실제 Git 반영 결과는 STATUS와 별도 검증 기록에 남깁니다. Git 태그의 로컬 생성과 원격 게시는 구분합니다.
