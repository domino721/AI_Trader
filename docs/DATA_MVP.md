# 데이터 수집·검수 MVP — WBS 1.1–1.8

계획 v1.1.0 / CR-0001. 코드·오프라인 검증과 실제 공급자 연결 결과를 구분합니다. 최신 상태는 [WBS](WBS.md)와 [STATUS](management/STATUS.md)가 기준입니다.

## 구현 범위

- 종목군 `research-smoke-v1`: AAPL, MSFT, GOOGL, AMZN, JPM / ETF SPY, IWM. 수집 검증용 고정 표본으로 당시 투자 가능 종목군·생존편향 검증이 아닙니다.
- Yahoo chart: 공급자가 제공한 OHLCV, 별도 조정종가, 현금 배당·주식 분할 비율. OHLC에도 소급 분할 조정이 반영될 수 있으므로 거래 당시 원주가·체결용 가격으로 인증하지 않습니다. 현재 시점에 받은 수정 이력을 과거 이용 가능 자료로 소급하지 않습니다. 운영 공급자의 이용권·정확성·지속성은 미확정입니다.
- SEC submissions: CIK 확인, 공시 번호·유형·공시일·대상 기간·수락 시각·원문 링크. 관련 과거 submissions 파일은 최대 12개까지 수집하고, 초과 시 실패로 표시합니다. 공시가 없는 기간은 정상일 수 있습니다. 미수집과 0건을 구분합니다.
- SEC 공시 본문/XBRL의 추출·단위 정규화·정정에 따른 당시 재무지표 재구성은 아직 없습니다. WBS 2.1/4.1에 남아 있습니다.
- XNYS 캘린더로 공통 미국 거래 세션·조기 폐장·휴장을 처리합니다. NASDAQ 개별 종목의 특수 거래정지나 공급자 누락을 휴장으로 간주하지 않습니다. 기본 범위는 최근 완료된 20개 세션이며 한 번에 최대 366일 범위입니다.

## 사용법

```bash
cd /workspace/AI_Trader
bash scripts/setup.sh
uv run --frozen ai-trader data collect
# 작은 범위, 특정 종목으로 접속 점검:
uv run --frozen ai-trader data collect --start 2026-01-05 --end 2026-01-06 --symbols AAPL SPY
# 원격 변경·정정을 확인하려면 캐시 대신 다시 수집:
uv run --frozen ai-trader data collect --start 2026-01-05 --end 2026-01-06 --symbols AAPL SPY --refresh
uv run --frozen ai-trader data replay <64자리-snapshot_id>
```

`collect`는 기본적으로 성공한 요청의 체크포인트를 재사용합니다. 실시간 최신값을 자동 보장하는 주기 수집기는 아니며, 갱신은 `--refresh`로 명시합니다. 갱신 실패 시 이전 캐시로 조용히 대체하지 않습니다. CLI 종료 코드는 승인 0, 차단/격리 2, 잘못된 요청·파일/무결성 오류 1입니다. 유효한 가격만 받아도 필수 기업 공시 수집이 실패하면 승인하지 않습니다. ETF에는 이 MVP의 기업 재무 공시 요구를 적용하지 않습니다.

환경 설정에서 `query1.finance.yahoo.com`, `data.sec.gov`, `www.sec.gov` 접근이 필요합니다. SEC 수집에는 실제 연락 정보가 포함된 `AI_TRADER_SEC_USER_AGENT`를 설정합니다. 예시 연락 주소는 사용하지 않습니다. 이는 요청 헤더에만 넣고 원본·영수증·스냅샷·로그·Git에는 저장하지 않습니다. 환경 설정 초안 저장과 현재 머신 반영은 다릅니다.

## 저장과 재생

기본 `.local/market` 아래에 저장하며 Git에서 제외합니다.

| 경로 | 내용 |
| --- | --- |
| `raw/<sha256>.json` | HTTP 200 원본, 내용별 중복 제거 |
| `receipts.db` | 요청별 최근 성공 체크포인트, 수신 시점·원본 해시, 값 없는 시도 결과 코드 |
| `snapshots/<id>.json` | 검수 통과한 불변 연구 스냅샷과 품질 보고서 |
| `quarantine/<id>.json` | 실패/격리 결과, 빠진 입력과 원인 |
| `normalized/<id>/*.parquet` | 승인된 가격·기업행위·공시 메타데이터, DuckDB로 질의 가능 |
| `normalized/<id>/exports.json` | Parquet 무결성 검사 해시 |

정규화는 Decimal·날짜·시간대가 있는 계약을 사용합니다. 각 스냅샷은 원본·수신 시점·종목군·정규화 결과·품질 판정에 대한 해시로 식별합니다. `--refresh` 결과는 새로운 버전으로 남고 이전 스냅샷과 원본을 덮어쓰지 않습니다. 같은 데이터/체크포인트로 다시 실행하면 동일 ID를 얻습니다.

`replay`는 스냅샷과 원본/Parquet 무결성을 확인하고, 승인된 스냅샷의 **당시 영수증에 고정하여** 네트워크 없이 파싱·검수를 다시 수행합니다. 최신 체크포인트가 다른 버전으로 갱신돼도 예전 원본을 사용합니다. 차단된 스냅샷은 무결성만 확인하고 외부 실패 재현을 성공으로 표시하지 않습니다.

API는 `/data/snapshots/{snapshot_id}`에서 저장된 결과를 조회합니다. API 요청이 외부 수집이나 주문을 시작하지 않습니다. 합성 데모의 입력과도 아직 연결하지 않았습니다.

## 수집·검수 정책

- 요청은 HTTPS·고정 호스트로 제한하고 TLS 검증을 유지합니다. SEC 파일 이름과 페이지 범위를 검사합니다. 원문에 포함된 임의 URL을 따라가지 않습니다.
- 단일 수집 프로세스에서 SEC는 요청 간 1초 이상 간격, 가격은 0.25초 간격을 둡니다. 429/일시적 5xx·통신 시간 초과만 최대 3회 재시도합니다. 짧은 Retry-After를 지키고 5초 초과 대기 지시는 반복 강행 대신 지연 필요 상태로 반환합니다. 영구 오류·프록시 거부는 반복하지 않습니다.
- 행 길이 불일치·null·잘못된 기업/통화/CIK·잘못된 수치의 응답은 사용하지 않습니다. 원본이 있으면 보존하고 실패 원인을 보고합니다.
- 독립 검수는 예상 거래일 커버리지·중복·양수 가격·OHLC 관계·음수 거래량·시간 경계·중복 기업행위·미래 공시를 확인합니다. 0 거래량은 경고로 남깁니다. 값 채우기나 이상치 삭제로 통과시키지 않습니다.
- 기본 승인은 **연구용 수집/정규화**에 한합니다. `historical_backtest_approved=false`, `trading_approved=false`를 항상 표시합니다. 현재 조정주가·종목군·공시 메타데이터만으로 당시 시점의 투자 판단/재무정보가 완성되지 않습니다.
- 데이터 신선도는 선택한 완료 세션 범위의 완전성까지 확인합니다. 주기 운영의 최신 공시 확인, 계좌/미체결 신선도, 종목별 거래정지, 본문/XBRL 정정 의미 검수는 후속 단계입니다.

## 검증 근거

`tests/test_data.py`는 가짜 HTTP 응답으로 어댑터 계약·실패 복구·품질 게이트·해시·Parquet·오프라인 재생·조회 API·CLI 종료 코드를 확인합니다. 실제 원격 응답으로 테스트를 통과했다고 표현하지 않습니다. 실제 접속 기록과 필요한 환경 변경은 [STATUS](management/STATUS.md)에 별도로 남깁니다.

2026-10-15 실제 주식/ETF 가격·배당·분할 및 SEC 공시 메타데이터 수집, 갱신 후 원본 고정 재생과 HTTP 조회를 확인하여 WBS 1.6–1.8을 완료했습니다. [검증 기록](management/DATA_VALIDATION_2026-10-15.md)에 실제 스냅샷과 수정 전 차단을 함께 보존합니다. SEC의 정상 상대 문서 경로는 허용하며 `.`·`..` 및 외부 URL 등은 거부합니다. 연구용 MVP의 완료이며 공급자 운영 이용권·PIT·백테스트/거래 승인을 뜻하지 않습니다.

새 NumPy와 pandas/거래소 캘린더 조합에서 발생한 호환 경고를 확인하여 NumPy를 `>=2,<2.4`로 제한하고 잠금파일을 갱신했습니다. 경고나 검증을 비활성화하지 않았습니다. 설치는 계속 `uv sync --locked`를 사용합니다.
