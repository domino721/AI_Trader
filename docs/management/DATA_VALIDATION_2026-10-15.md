# 실제 데이터 MVP 종료 검증 — WBS 1.6–1.8

2026-10-15 (한국 시간), 계획 v1.1.0 / CR-0001. 모의 HTTP 테스트와 별도로 현재 클라우드에서 실제 공급자 기능 요청을 실행했습니다. 검증 범위·선행 순서·기준 일정은 변경하지 않았습니다.

## 실행 환경과 접근

- 새 환경의 정책 파일에서 `query1.finance.yahoo.com`, `data.sec.gov`, `www.sec.gov` 허용을 확인했습니다. 실행 도구의 네트워크 권한을 사용하고 기존 프록시·TLS 검증을 유지했습니다.
- `AI_TRADER_SEC_USER_AGENT`의 런타임 존재를 값 출력 없이 확인했습니다. 실제 SEC 요청이 식별 검사를 통과하고 HTTP 200으로 응답했습니다. 연락 정보·헤더·비밀 값은 기록하지 않았습니다.
- 환경 상태 도구의 정책·변수 readiness는 `unknown`입니다. 상태 도구가 준비 완료를 인증했다고 하지 않으며 아래 실제 요청과 앱 동작으로 기능 결과를 판단합니다. 환경 게시 UI나 다음 인스턴스 복원까지 검증한 것은 아닙니다.
- `bash scripts/setup.sh`로 잠금 설치와 doctor를 통과했습니다. 최초 네트워크 권한 없는 설치의 `Operation not permitted`는 권한 적용 후 해결됐습니다. 의존성 선언·잠금파일을 변경하지 않았습니다.

## 실제 수집 결과

아래 명령은 저장소 루트에서 실행했습니다. 기본 종목군은 AAPL/MSFT/GOOGL/AMZN/JPM/SPY/IWM입니다. 원본은 Git 제외 `.local/market`에 보존하며 표에는 요약만 기록합니다.

| --- | --- | --- | --- | --- | --- |
| 최초 `--refresh` | 2026-01-05–06 / 7개 | 14 | 1 | 242 | 종료 0, 연구용 승인 |
| 같은 요청 캐시 재실행 | 같은 범위 / 7개 | 14 | 1 | 242 | 동일 스냅샷, 외부 요청 없음 |
| 최근 구간 `--refresh`, 수정 전 | 2026-09-17–10-14 / 7개, 20세션 | 140 | 2 | 0 | 종료 2, SEC 경로 파싱 실패 5건, 차단 원본 보존 |

| 분할 구간 `--refresh` | 2020-08-28–31 / AAPL | 2 | 1 | 0 | 종료 0, 2020-08-31 분할 비율 4 확인 |

```bash
uv run --frozen ai-trader data collect --start 2026-01-05 --end 2026-01-06 --refresh
uv run --frozen ai-trader data collect --start 2026-01-05 --end 2026-01-06
uv run --frozen ai-trader data collect --refresh
# SEC 경로 수정 후, 같은 실제 원본을 캐시에서 재처리:
uv run --frozen ai-trader data collect --start 2026-09-17 --end 2026-10-14
uv run --frozen ai-trader data collect --start 2026-01-05 --end 2026-01-06 --refresh
uv run --frozen ai-trader data collect --start 2020-08-28 --end 2020-08-31 --symbols AAPL --refresh
```

이번 실제 요청의 성공 영수증은 Yahoo 22회, SEC 16회입니다. 이는 재시도·캐시 호출을 포함한 가짜 테스트 수가 아닙니다. 각 7개 종목 수집은 Yahoo 7개와 SEC 5개 영수증을 갖습니다. SEC의 빈 공시 구간은 요청 성공·검수 후 0건으로 기록되며, 수집 실패와 구분됩니다. 모든 채택 공시의 수락 시각에 시간대가 있고 `accepted_at <= observed_at`을 확인했습니다. 실제 공시 본문은 내려받지 않았습니다.

## 수정한 결함과 회귀 검증

실제 SEC `primaryDocument`에는 `xslF345X05/ownership.xml` 같은 정상 상대 경로가 있습니다. 기존 파일명 전용 정규식 때문에 최근 구간의 5개 기업 공시가 모두 `malformed_response`로 차단됐습니다. 경로 구성요소를 허용하되 `.`·`..`, 절대 경로·외부 URL·빈 구성요소·역슬래시·퍼센트 인코딩·쿼리·프래그먼트는 계속 거부합니다. 출처 URL은 기존 SEC 호스트와 공시 번호 디렉터리 아래에 구성하며 임의 URL을 따라가지 않습니다.

정상 경로의 인용·재생 및 잘못된 경로의 차단/원본 보존에 대한 테스트 14개를 추가했습니다. 기존 ‘SEC 식별 정보 없음’ 테스트 2개는 `sec_user_agent=None`을 명시하여 실제 런타임 값의 영향을 제거했습니다. 실데이터를 테스트 fixture에 복사하지 않았습니다.

최종 `bash scripts/check.sh`는 불변 기준선·WBS·Ruff·포맷 검증 및 **81 passed**로 통과했습니다. 데이터 테스트는 이 중 50개이며 실패·스킵·테스트 경고는 없습니다. API 검사가 필요한 로컬 소켓도 실행 도구의 네트워크 권한 아래 검증했습니다. 0.2.0 sdist/wheel을 빌드했고 의존성 선언·잠금파일은 바꾸지 않았습니다.

- `--refresh` 후에도 최초·최근·분할 승인 스냅샷을 당시 영수증에 고정하여 네트워크 없이 동일하게 재생했습니다. 원본 및 Parquet 체크섬 검증을 포함합니다. 차단 스냅샷의 무결성 확인을 재생 성공으로 세지 않았습니다.
- 루프백 API를 실제로 시작하고 최근 승인 결과를 `/data/snapshots/{id}`에서 HTTP 200으로 조회했습니다. CLI와 같은 140개 가격·1,926개 공시, 연구용 승인 및 백테스트/거래 불승인을 확인했습니다. 합성 데모 HTTP 스모크도 별도로 통과했습니다.

## 종료 게이트와 남은 한계

WBS 1.5의 오프라인 검증에 더해 실제 주식/ETF 가격·배당·분할, SEC 식별 정보·공시 시각·재수집, 불변 원본·갱신·재생·조회 근거를 확보했습니다. 이번에 발견한 필수 품질 오류는 수정했고 최근 실제 원본 재검수도 통과했습니다. WBS 1.6·1.7·1.8을 완료로 기록합니다.

모든 승인 결과에 `research_only` 경고가 남습니다. 이 게이트는 연구용 데이터 MVP의 연결·정규화·재현성 검증입니다. Yahoo가 제공하는 OHLC를 거래 당시 원주가로 인증하지 않으며 공급자의 소급 분할/배당 조정을 검토해야 합니다. 별도 조정종가와 구분해 저장한다는 사실만으로 실제 체결용 가격이나 PIT 적합성을 보장하지 않습니다.

운영 공급자 이용권·재배포·지속성, 당시 종목군·상장폐지·과거 이용 가능 시점, 본문/XBRL 의미 검수·정정 이력, 주기 신선도와 거래정지는 후속 검증입니다. `historical_backtest_approved=false`, `trading_approved=false`를 유지합니다. 실제 LLM·RAG·백테스트·브로커 연결·수익성은 이번 검증 대상이 아닙니다. 다음 선행 작업은 WBS 2.1의 자료·권한·출처·시점 계약입니다.
