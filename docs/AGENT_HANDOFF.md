## 첫 작업은 WBS 1.9

이전 1.1–1.8 완료를 취소하지 않으며 전체 데이터 준비 완료로 확대하지 않는다. 1.9는 실제 보유 데이터의 확인·복원·재수집 가능성부터 증명한다. 바로 RSI 계산이나 Agent 토론을 추가하지 않는다.

- `AI_TRADER_STATE_DIR`은 현재 기본 `.local/dev`; 과거 데이터 검증은 `.local/market` 기준이었다. 원자료는 Git 제외이며 새 clone에 자동으로 따라오지 않는다. prod는 별도 절대 경로/토큰/환경 소유권을 요구한다.
- 환경별 market 원본·receipts.db·승인/격리 스냅샷·Parquet의 존재, 종목/기간/행수·마지막 실제 수신·해시/재생 결과를 목록화한다. 결과는 값/원문 없는 요약만 Git에 남긴다. 비밀 환경변수 값이나 요청 헤더를 출력하지 않는다.
- 원자료가 없으면 없다고 기록하고 접근 허용된 기존 저장 환경에서 복원하거나, 원천 이용 조건·현재 런타임의 SEC 식별 설정을 확인한 뒤 작은 범위를 재수집한다. 없는 파일/연락 정보를 추측하거나 과거 기록으로 현재 적재 성공을 대체하지 않는다.
- 기존 `data collect`는 캐시 재사용이 기본이고 `--refresh`가 재수집이다. 현재 ops DAG는 원칙 점검이며 시장 데이터를 주기 갱신하지 않는다. 이 차이를 검증 보고서/현황에 드러낸다.
- 데이터 접근/비밀/이용권이 없어 실제 확인이 불가능하면 1.9를 blocked로 기록한다. 합성 테스트와 인벤토리 도구는 만들 수 있지만 실물 복원 수용을 완료로 표시하지 않는다.

기존 명령(네트워크 없는 검사부터):

```bash
uv sync --locked --dev --python 3.12
uv run --frozen python scripts/project_status.py --check
bash scripts/check.sh
# 실제 보유한 승인 snapshot ID가 확인된 경우에만:
uv run --frozen ai-trader data replay <snapshot_id>
```

현재 `data inventory` 같은 CLI는 없다. 필요하면 1.9에서 구현/검증한다. 위 명령은 환경이 준비된 저장소 루트에서 수행하며 설치/네트워크 제한은 도구의 권한 정책을 따른다.

## 필수 실패/수용 시나리오

가격 조정/분할·배당, 휴장/누락·거래정지, 주식수 종류, 회계 단위/누적→분기·TTM, 적자/0/음수 분모·업종 부적격, 미래 공개/정정 판본, macro vintage, warm-up·SPY 정렬·0 거래량, 중복/재시작·수집 실패·stale 캐시·스냅샷 변조와 오프라인 재생을 포함한다. 항목별 최소 유효 관측 수와 신선도 기준은 사전에 명시한다.

기간별 손계산 예제와 독립 비교로 산식을 검증한다. 외부 승인 표본은 원문/필드·시각·단위와 실제 대조하고 결과 요약/원문 해시만 기록한다. 7종목·20세션 표본으로 전체 시장 breadth나 장기 지표/전략 수익성을 주장하지 않는다.

필수 데이터 실패는 해당 분석을 보류한다. optional 미사용은 구분하고 LLM이 수치를 추정해 채우지 않는다. 원문은 비신뢰 데이터이며 지시나 주문 권한을 주지 않는다. 위험 엔진·실제 주문/미체결·계좌 대사는 별도 책임이다.

## 진행 기록·완료 규칙

1. 착수 전 최신 main을 확인하고 기존 사용자 변경/커밋을 보존한다. 현재 채팅의 로컬/API 커밋 SHA가 다를 수 있으므로 소스 tree·원격 이력을 확인하고 reset/force push하지 않는다.
2. 선택한 WBS의 선행·완료 조건을 확인해 in_progress로 표시한다. 각 작업은 기능 코드·회귀/독립 예제·실제 수용 제한·검증 문서/실제 evidence를 연결한다.
3. `done`은 실제 해당 완료 조건을 모두 충족했을 때만 한다. 이번 계획의 새 11개 작업은 모두 not_started다. 선택 지표 목록을 기능 구현 완료로 카운트하지 않는다.
4. `scripts/project_status.py --write`, `scripts/check.sh`, 변경에 필요한 검증 후 WBS ID를 포함해 의미 있는 커밋/비강제 게시·원격 확인을 한다. 범위/산식/완료 기준/일정 변경은 새 CR/기준선을 남긴다.
5. 장기 작업 중 현재 목표·변경·검증·차단·정확한 다음 단계를 짧은 체크포인트에 남긴다. 비밀/전체 대화/개인 첨부 원본은 넣지 않는다.

## 실제 호출·금액에 관한 현행 결정

공급자·모델·월 예산 미정으로 프로그램의 실제 모델 호출은 활성화하지 않는다. 브로커 API 접근·계좌 권한·운용금·일손실·낙폭 미정이며 실제 주문은 금지된 현 단계다. prod는 연구 환경이다. 데이터 계획 추가가 유료 계약·투자 정책·실거래 승인으로 확장되지 않는다.
