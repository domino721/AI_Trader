# CR-0002 — 실제 운용을 위한 무결성·환경 분리·운영 관측 기반 선행

- 날짜: 2026-10-18, Asia/Seoul. 실행 계획 1.1.0 → 1.2.0 (minor).
- 근거: 사용자가 제3자 관점의 재검토와 실제 트레이딩에 활용할 수준으로의 개선을 명시적으로 요청함. 기존 미국 주식/ETF·일봉·연구→백테스트→브로커 모의→별도 실거래 승인 순서 유지.
- 결정: 운영 준비를 후반까지 미루지 않고 공통 기반 0.3–0.6을 추가한다. 실제 주문·미정 투자금/손실 한도·타인 계좌 권한·유료 모델 호출은 이 요청으로 자동 승인하지 않는다.

## 발견 사실과 변경

검토 기준 원격 8b53bdd. 저장된 지식 스냅샷의 무결성을 검색 전에 검사하지 않는 결함을 재현했다. 원문 구간 48,000자 제한의 무표시 절단과 청크 시작점 계산의 누락 가능성도 확인했다. 파서/청크 버전을 올리고 변조·메타데이터 불일치·중복·누락·레거시 인덱스를 거부하며 원문을 다시 색인하게 한다. 기존 원본과 검증 이력은 보존한다.

기존 단일 .env/.local, 기본 응답만 확인하는 health, 수동 개별 CLI와 분산된 결과 기록을 보완한다. 단일 집 데스크탑을 목표로 개발/테스트/운영 상태 경계, 운영 API 접근 통제, 영속 실행/단계 상태, heartbeat·중단 판정, 중복 실행 방지, 실패 시 후속 중단, 현황판과 로컬 경보, 일관된 백업/복원 검증을 구현한다. 첫 DAG는 원칙 문서 검증·색인·고정 검색 평가·오프라인 모델만 사용한다. 실제 모델/브로커 작업의 미구현을 표시하고 성공으로 가장하지 않는다.

## WBS·일정·완료 조건

- 0.3: 환경별 상태 경계·운영 API 인증·실제 저장소 readiness (0.2·2.3 뒤, D+23–25).
- 0.4: 2.3 및 0.3 뒤에 단일 호스트 DAG·영속 상태·중복/중단/후속 차단 검증 (D+25–28).
- 0.5: 0.4 뒤에 현황판·경보 조회·백업/복원 검증 (D+28–30).
- 0.6: 0.5 뒤에 실제 집 데스크탑 재부팅/절전/네트워크 단절/복원·접근 통제 수용 검증 (D+30–31). 외부 검증 전 미완료 유지.
- 3.2는 3.1과 0.6이 선행한다. 이후 미착수 작업의 상대 일정을 선행 조건에 맞춰 재계산한다. 3.1의 기존 오프라인 실적은 보존하고 잔여 실제 연결 작업은 D+31 이후로 재예측한다. 3.1은 진행 중이며 실제 공급자·모델·월 예산 결정은 여전히 필요하다.
- 5.3은 브로커 단계의 거래 일정·계좌 신선도·알림/운영 조회를 담당하며 공통 기반과 별도로 유지한다. 6.x는 실제 자본/권한/위험 한도 승인 뒤에만 진행한다.

D+n은 기존과 같은 상대 작업량 초안이며 마감일 약속이 아니다. 운영 기반 구현은 실거래 준비 완료나 전략 성과 입증을 의미하지 않는다. 기존 done 작업·외부 증거를 소급 삭제하거나 이번 모의 검증으로 외부 검증을 대체하지 않는다.

## 대안·비용·검증 영향

대안은 기존 순서를 유지하거나 처음부터 분산 워크플로 서비스를 추가하는 것이다. 단일 호스트 규모에서 필수 관측·복구 경계를 우선 검증하고 추가 상시 서비스/유료 서비스를 요구하지 않는다. 필요 시 성숙한 외부 실행기로 교체할 수 있게 단계 실행과 저장을 분리한다. 일반 모델 호출과 실제 주문은 계속 비활성화한다.

1.0 설계 manifest 및 1.1 WBS/해시는 불변으로 보존한다. 1.2 WBS/해시·변경요청을 추가하고 검증기를 등록된 모든 기준선에 대해 검사하도록 확장한다. 단위 테스트 외에 동시 실행·프로세스 중단·변조·인증 실패·환경 혼용·백업 복원 시나리오를 검증한다. 실제 브로커/명의자 권한·자금/손실 한도·집 데스크탑 수용은 별도 잔여 게이트다.
